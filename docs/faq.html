Frequently asked questions

Everything below describes the tool as it actually runs today.

The tool

Who can use Neon Escape?

Only its owner. There is no sign-up, no hosted service and no way for anyone else to connect an account. It is a script running on one private server, working on one TikTok account — the owner's own.

Is the content original?

The animation is generated entirely from code — no stock footage, no screen capture, no third-party clips. The soundtrack is synthesised note by note from MIDI files the owner places on the server; no audio recording is reused.

How long is a video?

Between one and three minutes. A clip runs past the one-minute mark and then ends on the next completed sphere, so its exact length depends on how the run goes.

Why does the ball's speed keep changing?

Because it is a real simulation: gravity slows it on the way up and speeds it on the way down, and each bounce loses a little energy. The only correction is a floor that guarantees it can always climb back out of a ring, so it never gets trapped at the bottom.

The TikTok integration

Which TikTok permissions does it use, and why?

user.info.basic confirms which account the tool is connected to, so it can be shown in the operator's logs and a wrong account is caught immediately. video.publish posts the generated videos. No other scope is requested.

Does it read, download or repost anyone else's content?

No. It never reads a feed, never downloads a video, and never touches another account. The only thing it sends to TikTok is a file it just rendered itself.

How often does it post?

Twice a day, at a randomised minute inside a late-morning and a late-afternoon window. Publishing can be paused at any time from the configuration, in which case videos are simply kept on the server.

What happens to the access tokens?

They are stored in a single file on the owner's private server and refreshed automatically. They are never shared, never sent anywhere else, and revoking the app from TikTok's settings invalidates them immediately.

Operations

What does it run on?

A small Python server with no display: frames are drawn in memory and piped straight into an encoder. A full video renders in a few minutes on a modest machine.

How does the owner know it is working?

Each step — startup, which account is connected, the track being used, rendering progress, the publish result and any error — is reported to a private channel the operator owns, along with the finished video.

What happens when something fails?

A failed run is retried a few minutes later, and the rendered video is kept rather than discarded. If TikTok refuses an upload, the reason is reported in plain language along with what to do about it.

Anything else? The project is a personal one; questions can be raised through its repository.
